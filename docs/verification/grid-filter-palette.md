# Grid filter and command palette verification (P17-17)

Status: **automated done, agent pass partial (P18-28), manual pending.** The owner ticks the boxes below; the `Result` column stays blank until then.

## Automated (done)

**Grid filter.** `tests/Shared/GridFilterFlowScenario.cs` drives, per engine, a real `QueryTabViewModel` with a real `SessionManager`, the real provider and a live connection, on a 5-row table `gf_t` (integer key, `decimal(10,2)`, accented text with one NULL, date-time, boolean where the engine has one, guid). One test class per driver project (`GridFilterFlowTests.cs`): SQLite always runs, PostgreSQL / MySQL / SQL Server are Docker-gated (`rtk pwsh eng/run-docker-tests.ps1 -Engine <engine> -Filter '--filter-class *GridFilterFlowTests'`). Covered:

- A typed filter per category: `>` on the decimal (100 and 250 match, a number order and not a text order), `>=` on the date-time, `Contains` with accents and case (`émi` finds `Émile`), `IsNull` on text and on the boolean, `Equals` on the boolean; the footer text counts matching rows of loaded rows. Two filters combine with AND; removing a chip and `ClearFilters` restore the unfiltered grid.
- The value list of a column: values with counts (`Émile` 2, `NULL` 1, ...), the NULL row, applying two values produces an `In` filter, and an `In` set holding NULL keeps the NULL row.
- Sort ascending then descending (then none on the third click) on the number, the text (NULL first, accents sorted with their letter) and the date-time.
- Search over several columns (a text column, a date column, no match).
- A grid edit is refused while a filter is active (`ReadOnlyReason` is `results.readOnly.filtered`, `TrySetCell` refuses, `AddRow` returns -1); after `ClearFilters` the same edit commits and the row holds the new value in the database.
- Pending edits block adding a filter, a sort or a search; after reverting them a filter works again.
- Export while filtered still writes every loaded row (CSV: header and 5 rows, with 2 rows shown).
- A 50,000-row result generated by the engine (`generate_series`, recursive CTE, `top (50000)` over a cross join): `AddFilter` returns at once (the rebuild runs on a worker), a filtered view and a full sort settle within a generous bound, descending sort starts at 50,000.

SQLite has no date or boolean type: its date column is text (the `>=` date filter is skipped, the sort and the search still run on the ISO text) and its flag is an integer.

**Command palette.** `tests/Squill.Presentation.Tests/Palette/PaletteFlowTests.cs` drives a real `WorkspaceViewModel` with two connected fake servers (a Production `prod` and a Staging `stage`, the same table name `commands` on both): `comm` in `All` returns the objects of both connections with their environments, then actions, then history (newest first, order of decision 13); `>` lists actions only and `Commit` is disabled without a transaction; `#` finds a routine and a trigger; `!` lists history newest first and `Enter` appends the statement to the active tab without sending anything to the connection; `:3` moves the caret to line 3; `Enter` on a table of the non-active connection activates that connection and opens its tab; `Ctrl+Entrée` opens a query tab with the quoted `SELECT *`; closing and re-opening resets the text and the mode; a language switch changes the titles and the section captions. The key handling and focus of the two heads are covered by their own tests (P17-15, P17-16), not here.

Not covered by the scenarios: anything drawn or focused in a window (below), the debounce of the search box, the 100,000-row result in a real window, a filter on a result that is still streaming (the view rebuilds as rows arrive; only unit-tested in `FilteredGridDataSourceTests`).

## Known limits (ADR 0014)

These are decisions, not bugs; do not report them. Verify that each is visible as described.

- The filter and the sort are client-side over the rows already loaded (no server round trip); `x lignes sur N chargées` counts loaded rows, and a truncated result says so with a `+`.
- The grid is read-only while a filter, a search or a sort is active (the `filtre actif` marker), and a filter cannot start while edits are pending.
- Export writes the whole committed result, never the filtered rows.
- Not built (no feature behind it): freeze / hide / fit width, the row side panel, block size and infinite scroll, the cell sum, filtering rows that carry edits, OR groups, the `@ Symboles` mode and the `FICHIERS` section of M13.
