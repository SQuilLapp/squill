# Phase 14 - shared recipe (SQL completion: join conditions and a better popup)

Read by every card of phase 14. No mockup: the popup is the control's own suggest widget (LoomEditor, both heads since P5-13 / ADR 0002); the cards change **what the providers return**, not how the widget draws.

## 1. What exists today (audit of 2026-11-10, read before changing anything)

- `src/Squill.Sql/Completion/`: `ISqlCompletionProvider.GetCompletions(SqlRequest)`; `KeywordCompletionProvider`, `SchemaCompletionProvider`, `FunctionCompletionProvider` (in `Functions/`) merged by `CompositeCompletionProvider` (ordered by `SortText`, default `"2" + Label`); `CompletionFilter` (prefix then contains, only used by the plain-text editor); `IdentifierQuoting.Quote` (per-dialect quoting, PostgreSQL capitals quoted); record `CompletionItem(Label, Kind, InsertText, Detail, SortText, ReplaceRange)`.
- `SchemaCompletionProvider` already: tables / views / schemas after `FROM`, `JOIN`, `INTO`, `UPDATE`, `,` in a FROM list; columns of the visible sources in SELECT / WHERE / ON / GROUP BY / HAVING / ORDER BY / SET with `alias.` and `schema.table.` qualifiers; column list after `INSERT INTO t (`; and, **only once the user is in an `ON` clause**, `JoinConditions`: one `a.fk = b.pk` snippet-kind item per foreign key between two visible tables (child side written first, composite keys joined with `AND`, aliases used).
- **Gaps** this phase closes: picking a table after `JOIN` inserts the bare name only (no condition, no alias); a table outside the default schema is inserted unqualified; a column name shared by two sources is inserted unqualified (ambiguous column error); keywords are always upper case (the `FormatterKeywordCase` setting is ignored); `FULL JOIN` is proposed on MySQL; no documentation text; no statement snippets; the popup does not open by itself after `JOIN `; items are ranked by name only.
- `SqlRequest(Text, Offset, Dialect, Schema)`; `ScopeInfo(Clause, Sources)` from `SqlScopeResolver.Resolve(script, offset)` (sources of the innermost statement first, then enclosing statements, **no boundary between them**; derived tables and CTEs carry `DerivedColumns`); `JoinKind` (`Inner, Left, Right, Full, Cross, Comma`) in `Squill.Sql/Syntax/Statements.cs`.
- Schema model (`Squill.Core`): `SchemaSnapshot.FindTable(schema, name)`, `TableInfo.ForeignKeys` = `ForeignKeyInfo(Name, Columns, ReferencedSchema, ReferencedTable, ReferencedColumns, OnDelete, OnUpdate)`; composite keys are parallel lists; SQLite resolves an implicit target (`REFERENCES t` without a column) to the referenced primary key at read time, the three server engines always report the columns. Nothing needs to change in the readers.
- Presentation: `QueryTabViewModel` registers a private `SessionCompletionProvider` (adds `session.Schema` to the request, merges the keyword and schema providers; the function provider is not in that composite today, check `FunctionCompletionProvider` usage before P14-14). Heads: `src/Squill.App.Shared/LoomSqlProviders.cs` (linked into both heads; slices the script to the statement under the caret, maps `CompletionItem` to LoomEditor's, trigger characters `["."]`) and `src/Squill.App.WinUI/Editors/PlainSqlEditor.cs` (fallback editor with its own list and `Accept`).
- LoomEditor (package `0.5.0`, central version in `Directory.Packages.props`; the local checkout `D:\LoomEditor` is `0.6.0`, **use only what 0.5.0 has**; the members below are in its `LoomEditor.Core.xml`): `LoomEditor.Core.Languages.Features.CompletionItem` has `Label`, `LabelDetail`, `LabelDescription`, `Kind`, `Detail`, `Documentation` (`MarkdownString`), `SortText`, `FilterText`, `Preselect`, `InsertText`, `InsertTextRules` (`InsertAsSnippet`, `KeepWhitespace`), `Range` (`CompletionRange`), `CommitCharacters`, `AdditionalTextEdits`. Accepting an item (`SuggestController.Accept`) pushes an undo stop before and after, so **one Ctrl+Z reverts the whole insertion**; a plain `InsertText` is inserted as typed (not re-indented), a snippet goes through the snippet controller (`$0`, `${1:x}`, Tab moves between stops, `$`, `}` and `\` must be escaped in literal text). Item commands are not supported, so an item cannot trigger another action after insertion.

## 2. Decisions (final)

1. **All intelligence stays in `Squill.Sql/Completion`** (pure, no UI type, no reflection, AOT-safe); the heads only map fields. New types are `internal` unless a card says otherwise (`InternalsVisibleTo Squill.Sql.Tests` exists).
2. **Join rows are added above the unchanged table list.** After `JOIN ` (and the other table positions that are joins) the popup shows first one row per *relation* between the new table and a table already in the FROM list, then the plain table / view / schema rows exactly as today. A relation row is `Label` = `table` or `table alias`, `Detail` = `ON <condition>`, `InsertText` = `table[ alias] ON <condition>`, `FilterText` = the bare table name (so typing `ord` still finds it), `Kind` `Struct`, `SortText` group `"00"`. Typing the table name then accepting inserts name, alias and condition in one undo step; the caret ends after the condition.
3. **What counts as a relation** (`TableRelation`, P14-05), in this order of strength: (a) a foreign key of the new table to a visible table, (b) a foreign key of a visible table to the new table, (c) only when the new table has no foreign key relation with any visible table: a column of the same name (not `id`) that is a primary-key column of one of the two tables and exists in the other (the whole key for a composite primary key). Several foreign keys between the same pair give several rows (distinct `Detail`, the foreign key name in the documentation); a composite key is one row with the columns joined by ` AND ` in key order; a self-referencing key gives two rows (new alias references existing, existing references new alias) and forces an alias; a table already present in the FROM list is still offered (self join / second join of the same table) and forces an alias. Views have no foreign keys: they only get (c) never (a)/(b). A table with no relation at all gets no join row, only its plain row (same as today).
4. **Ranking of join rows**: strength (a/b before c), then the visible source closest to the caret first (the most recently joined source, so in `customers c JOIN orders o JOIN |` the relations to `o` come before those to `c`), then a table not yet in the FROM list before a repeat of one that is, then table name ordinal, then constraint name ordinal. Deterministic: tests assert full order.
5. **Side order of `ON`: the table already in the FROM list first, the new table second, for every join kind.** `ON existing.col = new.col`, never the other way, independent of which table holds the foreign key. Why: `=` is symmetric, so the written order cannot change the result of `INNER`, `LEFT`, `RIGHT` or `FULL`; which rows are preserved is decided by the join keyword, not by the side of the comparison. One rule that follows the order of the FROM list is easier to read and to test than four. The join kind only decides **whether** a condition is generated: `INNER`, `LEFT [OUTER]`, `RIGHT [OUTER]`, `FULL [OUTER]` and plain `JOIN` get `ON`; `CROSS JOIN`, `NATURAL JOIN`, a comma, `CROSS APPLY` / `OUTER APPLY` (T-SQL), and a join whose next token is already `ON` or `USING` get the plain table only. (If the owner prefers a kind-dependent order it is one switch in `JoinConditionText`, P14-08.)
6. **Alias policy** (`AliasGenerator`, P14-06): the new table gets an alias only when (i) a table of the same FROM list already has an alias, or (ii) the table (same schema and name) is already in the FROM list, or (iii) the relation is a self reference. Alias = lower-case initials of the words of the name (`order_items` -> `oi`, `Customers` -> `c`, camelCase split), at least one letter; on a collision with an existing alias or source name, or with a reserved word of the dialect, extend with the next letters of the first word, then digits. No `AS` (valid on every engine for table aliases, and Oracle forbids it). The existing sources keep their alias or, when they have none, their table name is used in the condition (never the schema-qualified name).
7. **Quoting**: every identifier goes through `IdentifierQuoting.Quote(name, dialect)` (backticks MySQL, brackets SQL Server, double quotes elsewhere, PostgreSQL quotes names with capitals); a table outside the default schema is inserted `schema.table` (P14-03). Quoting is decided per identifier, never by string replacement on the finished text. Oracle goes through the same code but is not verified live (no Oracle container in phase 14).
8. **A condition is never generated when it would duplicate or contradict the text**: caret inside an existing join (the next token after the typed word is `ON`/`USING`), `CROSS`/`NATURAL`/comma, the schema is unknown (`SqlRequest.Schema` null), the visible sources are all derived tables or CTEs (their columns have no keys). The ON-clause items (P14-09) skip a condition already present in the clause.
9. **No new setting** except what P14-14 reuses (`FormatterKeywordCase`). Whether to generate the condition is not configurable in this phase (the plain table rows are still in the list; known limit in the ADR).
10. **Performance**: a request must stay interactive on a schema of 5,000 tables with 10,000 foreign keys (relation search only looks at foreign keys of visible tables and at tables that reference them; no per-request index is built, a test with generous bounds guards against accidental quadratic work).

- `rtk dotnet build Squill.slnx -c Release -warnaserror` 0 warnings (cards touching the WinUI head also build `Squill.Windows.slnx`), `rtk bypass dotnet test --solution Squill.slnx -c Release` green, never weaken a test; an existing test that encodes behaviour this phase changes on purpose is edited **in the card that changes it**, with the reason in the commit message.
- XML docs as in `CLAUDE.md` (public and protected members, public members of internal types, one-line summary on every internal type; grep before committing), no `NoWarn`, no `#pragma warning disable`, no reflection.
- User-visible text (`Detail`, documentation) that is not SQL goes through `UiText` only where the head already does so for completion today; SQL keywords and identifiers are never translated. Check how `Detail` strings such as `"table"` / `"view"` / `"alias"` are produced today before adding one; if they are literals, keep literals and say so in the report (translation of popup details is out of scope for phase 14).
