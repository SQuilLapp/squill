# P20-40 - Grid: the in-place cell editor keeps a pasted multi-line text whole (both heads)

Status: todo
Depends on: P20-31

## Goal
Bug found by the P20-31 drive on the WinUI AOT exe (Done notes, path (a)): double-click a `ville` cell, `Ctrl+V` of a 298 KB indented JSON in the in-place editor, `Enter`: the cell holds only `{`. Silent data loss. The owner decided: the in-place editor keeps the **whole** text on paste and on commit, byte for byte (line breaks `\r\n` / `\n` as they were, indentation, length). The grid still draws one line (P20-31 `CellText.Preview`); only the stored value must be exact. Same fix in both heads: the Avalonia editor has the same single-line `TextBox` and the same sync code.

Files today: `src/Squill.App.WinUI/Controls/DataGridView.cs` (`_editor`, its `TextChanged` handler, `OnEditorKeyDown`, `SyncEditor`), `src/Squill.App.Avalonia/Controls/DataGridView.cs` (same members), `src/Squill.Presentation/Editing/GridEditController.cs` (`Begin`, `SetText`, `EditText`, `Commit`), `src/Squill.Presentation/Results/CellText.cs` (P20-31), `src/Squill.Presentation/Results/CellPreviewViewModel.cs` (the preview pane), the catalogs `src/Squill.Presentation/Localization/UiTextCatalogEn.cs` / `UiTextCatalogFr.cs`.

## Root cause (read in the code at `ef5c39a`)
1. The in-place editor of both heads is a **single-line `TextBox`** (`AcceptsReturn` left at `false`): WinUI `DataGridView.cs` line 21, Avalonia `DataGridView.cs` line 20. Neither head handles paste: the built-in paste of a single-line box inserts **only the first line** of a multi-line clipboard text (WinUI: seen in the P20-31 drive; Avalonia: its `TextBox` input sanitising drops every line after the first when `AcceptsReturn` is false; confirmed by the characterization test of this card).
2. The `TextChanged` handler (WinUI line 47, Avalonia line 40) then copies the box text into the controller (`c.SetText(_editor.Text)`), so `GridEditController.EditText` becomes `{` and `Enter` -> `Commit` -> `TrySetCell(EditText)` stores it. `CellEditorKinds.Sanitize` and `CellValueParser` are identity for text and JSON columns: the controller is not the cause, the box is.
3. Same loss, not yet seen in a drive, when the editor is **opened on a value that already has line breaks** (stored through the preview pane, read from the database): `SyncEditor` sets `_editor.Text = c.EditText`; the one-line box cannot hold it as is, so `_editor.Text != c.EditText` stays true. On WinUI `TextChanged` is raised asynchronously, after `_syncing` is back to `false`, so the handler pushes the box's text (cut or with line breaks rewritten) into the controller, and `Enter` writes it back.
4. Making the box multi-line (`AcceptsReturn = true`) does **not** give an exact value on WinUI: its `TextBox` returns every line break as `\r` (a `\r\n` clipboard text comes back changed), and a 298 KB value in a one-row box is unusable. The exact text must stay in the controller, not in the box.

## Design decisions (final)
- **Principle**: the controller (`GridEditController.EditText`) is the only owner of the text being edited. The box shows it as is when it is one line, and as a read-only one-line preview when it holds a line break. A paste goes to the controller, never through the box, whenever it carries a line break.
- **Enter semantics unchanged**: `Enter` commits (moves down), `Tab` / `Shift+Tab` commit and move, `Esc` cancels, as today in both heads. No key inserts a line break in the in-place editor (no `Shift+Enter` / `Alt+Enter` newline). Why: a grid cell editor is one row high, both heads and DataGrip commit on `Enter`, and a line typed through the box could not be exact on WinUI anyway (item 4 of the root cause); writing multi-line text is the job of the preview pane, which already has `AcceptsReturn = true`. Rejected: `AcceptsReturn = true` with `Enter` intercepted (changes `\r\n` on WinUI, a huge value in a one-row box), and normalizing line breaks (the owner wants the value exact).
- **Shared rules** (Presentation, unit tested, no UI type):
  - `CellText.IsSingleLine(string text)`: `true` when `text` holds none of `\r`, `\n`, U+000B, U+000C, U+0085, U+2028, U+2029 (a `SearchValues<char>`, one `IndexOfAny`; tabs do not count). XML doc. Update the `CellText` class summary: its preview is also what the in-place editor shows, read-only, for a multi-line value.
  - `GridEditController`:
    - `public bool IsMultiLine => IsEditing && !UsesDefault && !CellText.IsSingleLine(EditText);` (XML doc: the text holds a line break, so the one-line editor shows it read-only).
    - `public string EditDisplayText => IsMultiLine ? CellText.Preview(EditText) : EditText;` (what the box shows).
    - `public void PasteText(string text, int selectionStart, int selectionLength)`: does nothing when not editing; `ArgumentNullException.ThrowIfNull(text)`; when `IsMultiLine` or `UsesDefault`, the pasted text **replaces the whole value** (the box shows a preview or the default label, so its caret means nothing); otherwise it replaces `EditText[selectionStart .. selectionStart + selectionLength]` (both clamped to the text, a negative length counts as 0) with `text`, built once with `string.Concat` of spans; then `SetText(result)` (so `Sanitize` still drops line breaks for number columns, `Validate` runs, `EditStateChanged` is raised). No other normalization.
  - `Begin` and `Commit` are unchanged: a cell opened on a multi-line value gets `EditText` exact and `IsMultiLine` true, so `Enter` writes it back unchanged.
- **WinUI head** (`DataGridView.cs`):
  - `SyncEditor`: compare and set `_editor.Text` against `c.EditDisplayText` (not `EditText`); `_editor.IsReadOnly = c.IsMultiLine`; tooltip `c.Error ?? (c.IsMultiLine ? UiText.Get("results.multiLineEdit") : null)`; `AutomationProperties.SetHelpText(_editor, ...)` with the same hint (empty when single-line).
  - `TextChanged` handler: also return when `c.IsMultiLine` (the box holds the preview, never a value).
  - `_editor.Paste += OnEditorPaste` (raised by `Ctrl+V`, `Shift+Insert` and the context menu of an editable box): `e.Handled = true` at once; capture `SelectionStart` / `SelectionLength` before awaiting; read the text like `DataGridCanvas.PasteAsync` (`Clipboard.GetContent()`, only when it has `StandardDataFormats.Text`, `GetTextAsync()`); if the controller still edits the same cell: when `CellText.IsSingleLine(text) && !c.IsMultiLine`, `_editor.SelectedText = text` (native insert at the caret, undo kept, `TextChanged` flows as today); otherwise `c.PasteText(text, start, length)` (the `EditStateChanged` -> `SyncEditor` shows the preview).
  - A read-only box does not raise `Paste`: `_editor.PreviewKeyDown` handles `Ctrl+V` and `Shift+Insert` **only while `c.IsMultiLine`** (`e.Handled = true`, same clipboard read, `c.PasteText(text, 0, 0)`, which replaces the whole value). `Enter`, `Tab` and `Esc` already reach `OnEditorKeyDown` on a read-only box; check it in the drive.
  - Put the shared body in one `private async void` / `async Task` method used by both handlers; exceptions of the clipboard read are caught and ignored like `DataGridCanvas.PasteAsync` does (read it and copy its pattern).
- **Avalonia head** (`DataGridView.cs`), same behaviour:
  - `SyncEditor` / `TextChanged` / `IsReadOnly` / tooltip (`ToolTip.SetTip`) / `AutomationProperties.HelpText` as WinUI.
  - `_editor.PastingFromClipboard += ...` (`e.Handled = true`, `TopLevel.GetTopLevel(_editor)?.Clipboard` and `TryGetTextAsync()` as `DataGridCanvas.PasteAsync` line ~735 does), same branch: single-line text into a single-line value -> `_editor.SelectedText = text`, else `c.PasteText(...)`.
  - Read-only box: `_editor.AddHandler(InputElement.KeyDownEvent, handler, RoutingStrategies.Tunnel)` for `Ctrl+V` (the platform paste gesture, `TopLevel.PlatformSettings?.HotkeyConfiguration.Paste` if it is reachable, otherwise `Ctrl+V` and `Shift+Insert`) **only while `c.IsMultiLine`**.
  - The clipboard-to-controller step is an `internal void PasteIntoEditor(string text)` (the test project sees internals) so the headless test does not need a clipboard.
- **New key** (fr and en catalogs, parity and used-keys tests): `results.multiLineEdit` = `Multi-line value shown on one line: Enter keeps it, Ctrl+V replaces it, Esc cancels. Edit the text in the preview pane.` / `Valeur sur plusieurs lignes affichée sur une ligne : Entrée la garde, Ctrl+V la remplace, Échap annule. Modifiez le texte dans le volet d'aperçu.`
- **The preview pane is not changed** by this card. How to reach it (P20-31 could not): it has no toggle button; `CellPreviewViewModel.Refresh` opens it by itself when the **selected** cell is a `json` / `jsonb` column, a text starting with `{` or `[` and longer than one character, a value of at least `LongTextLength` (80) characters, or a value with `\n`; `Fermer` hides it until another cell is selected. P20-31 left `{` (one character) in `ville`, so the pane stayed closed. After this card's paste + `Enter`, select the cell again: the pane opens on the right of the grid (WinUI `QueryTabView` `body` column 2, splitter column 1).
- No `ItemsSource`, no `Application.Current.Resources[...]` brush lookups (P20-02 guard), no new package.

## Interaction with P20-33 ... P20-35 (long paste)
- This card goes **before P20-33**: P20-33 measures path E (in-place editor) and today the box inserts only the first line, so its numbers for E1 / E3 would measure a cut text. After this card a multi-line paste into the editor puts only the 500-character preview in the box (E1 becomes cheap for multi-line texts; still the full text for a long single-line one). P20-33 now depends on P20-40.
- P20-34 and P20-35 hook the editor's paste too (`.Paste +=` / `PastingFromClipboard`, `SelectedText = text`). They must **reuse this card's handler** for the in-place editor and only wrap it with the overlay for a long text (show, yield, call the same body, hide), not add a second handler. Their preview-pane handling is unchanged. Both now depend on P20-40 (P20-35 through P20-34).
- No overlap with P20-31 / P20-32 (drawing) beyond reusing `CellText.Preview`; P20-32 (Avalonia preview) is not needed by this card.

## Out of scope
- Typing a line break in the in-place editor, a multi-line in-place editor, making the preview pane paste exact (see open question), pasting a multi-line text into one cell with `Ctrl+V` on the grid (no editor open: still split into rows, tab-separated semantics), drag and drop of text into the editor, minifying JSON, the long-paste popup (P20-34 / P20-35).

## Risks
- If a read-only WinUI `TextBox` swallows `Enter` / `Esc` before `KeyDown` (step 1 to 3 show it), move those three keys to the `PreviewKeyDown` handler while `IsMultiLine` and say so.
- If the WinUI `TextBox.Paste` event is not raised for the context-menu paste, record it (keyboard paste is the main path); do not hook the context flyout by hand.
- Async clipboard read: the edit can end before the text arrives (the user pressed `Esc`); check `c.IsEditing` and the same `EditRow` / `EditColumn` before applying, otherwise drop the text.
- `SelectedText` on the single-line branch: if it loses undo on either head, record it (acceptable). If `TextBox.PastingFromClipboard` or a settable `SelectedText` is missing in Avalonia 12.1.6, stop and report with a proposed card fix (same rule as P20-35).
