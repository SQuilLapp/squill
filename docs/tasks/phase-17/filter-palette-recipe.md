## 1. What exists today (audit of 2026-11-16, read before changing anything)

- **Grid data.** `IGridDataSource` (`Squill.Presentation/Results`): `Columns`, `RowCount`, `IsComplete`, `IsTruncated`, `GetCell(long row, int column)`, `Changed` (raised on the UI thread). `StreamingGridDataSource` is the committed result (chunked arrays, appended while the reader streams, `Changed` throttled to 50 ms). `EditableGridDataSource` wraps it for a single-table result (pending edits, `RowState`, added and deleted rows) and is `ResultViewModel.DisplayGrid` when an `Editor` exists, otherwise `DisplayGrid` is the streaming source. Both heads bind **only** `ResultViewModel.DisplayGrid` (`QueryTabView.cs:691` WinUI, `QueryTabView.axaml.cs:317` Avalonia) and re-bind on its `PropertyChanged`; `CellPreviewViewModel` also reads `DisplayGrid`.
- **Selection and editing.** `GridSelection` (cell, rectangle, whole columns, row indexes are `DisplayGrid` rows), `GridEditController` + `ResultEditorViewModel` edit `Editor.Grid` by its row index. `ResultViewModel.ReadOnlyReason` is `loading` while streaming and a reason string otherwise; the heads draw the marker (`Modifiable · clé primaire id` / `Lecture seule · ...`) from it.
- **Export.** `ResultViewModel.ExportAsync` exports the committed `Grid` (never the pending edits) through `ResultFileWriter.WriteAsync(exporter, IGridDataSource, path, ct)`.
- **Not there**: no filter, no sort, no column menu, no in-grid search, no row side panel (the cell preview pane of phase 12 is a different thing). The M05 filter bar, column menu and row panel are listed as "not drawn" in `visual-spec.md` section 6 and 10.
- **Palette**: nothing. The title bar has a disabled placeholder search box (`search.placeholder` = `Rechercher objets, fichiers, actions...`, Avalonia `MainWindow.axaml` border `CommandSearch`, the WinUI twin in `MainWindow.Chrome.cs`; look it up). There is no action registry: commands are `[RelayCommand]`s of `WorkspaceViewModel` (`NewTab`, `CloseTab`, `Connect`, `Disconnect`, `OpenTable`, `NewTable`, `DesignTable`, `OpenDiagram`, `NewTerminal`, ...) and `QueryTabViewModel` (`Run`, `RunAll`, `FormatDocument`, `Cancel`, `Commit`, `Rollback`, `SetMode`, `Explain`, `Analyze`); the head-only ones (settings, about, update check, data folder, connection manager) are handled in the window code. Key bindings are defined per head (Avalonia `MainWindow.axaml` and `MainWindow.axaml.cs`: `F5` / `Ctrl+Enter` run, `Ctrl+Shift+F` format, `Ctrl+T` new tab, `Ctrl+W` close, `Ctrl+,` settings, `Ctrl+E` explain, `Ctrl+Shift+E` analyze, `Ctrl+Alt+C` / `Ctrl+Alt+Z` commit / rollback). `Ctrl+K` is bound to nothing.
- **Data for the palette**: schema objects in `ConnectionSession.Schema` (`SchemaSnapshot`: tables, views, materialized views, routines, triggers) for every open session (`WorkspaceViewModel.Sessions`); history in `IQueryHistoryStore.ListAsync(max, ct)` (oldest first, `HistoryEntry(At, ProfileId, Sql, Succeeded, RowCount, Elapsed)`); the explorer already opens a table (`OpenTableAsync`) and a definition (`DefinitionScript`); `ISqlEditor` has `Text`, `CaretOffset`, `Selection`. Environments: `ConnectionEnvironment` (colors by environment exist for the explorer and the tabs).

## 2. Decisions (final)

**Filter (M05)**
1. **Client-side, over the rows already loaded.** The filter and the sort never re-run the query and never go back to the server. While the result still streams, the view follows (new rows are tested as they arrive). On a truncated result the footer says so (the row limit still applies; the figure is "filtered of loaded"). A filter over the whole table is `WHERE` in the editor, not this feature.
2. **A view layer, not a change of the sources.** `FilteredGridDataSource` (P17-03) wraps the display grid and maps a view row to a source row. `ResultViewModel.DisplayGrid` returns the view while a filter, a search or a sort is active and the plain grid otherwise, so both heads keep binding one property.
3. **Read-only while a view is active.** Editing, adding, deleting and reverting rows are refused while a filter, search or sort is active (the edit controller and the heads show the reason `filtered`, text `Lecture seule · filtre actif` / `Read-only · filter active`), and a filter, search or sort cannot be switched on while the result has pending changes (the commands are disabled with the tooltip `Validez ou annulez les modifications avant de filtrer`). Clearing the view restores editing. This is the simplest rule that cannot corrupt row identity; filtering rows that carry edits is not built.
4. **Operators.** `Equals`, `NotEquals`, `Contains`, `StartsWith`, `EndsWith`, `GreaterThan`, `GreaterOrEqual`, `LessThan`, `LessOrEqual`, `IsNull`, `IsNotNull`, `In` (a set of values, produced by the value list of the column menu). Which operators a column offers depends on its type category (text, number, date/time, boolean, other). Comparisons are typed: the typed text is parsed with the existing `CellValueParser` for the column; text comparisons are case-insensitive (ordinal ignore case) and `Contains` / `StartsWith` / `EndsWith` work on the formatted cell text (`CellFormatter`). SQL NULL never matches anything except `IsNull` and an `In` set that contains the null entry; `NotEquals` does not match NULL either (three-valued logic reduced to "does not match"). Several filters are combined with AND; the search box is one more AND condition (contains, any column, formatted text).
5. **Sort.** One sort column at a time (click again to flip, a third click clears), stable, NULL first ascending and last descending, typed comparison by column category, text with `StringComparer.CurrentCultureIgnoreCase`. The sort works on the loaded rows and is recomputed when rows arrive (while streaming it is applied when the stream completes or every 1 s, whichever is simpler to prove; the card says which).
6. **Chip text** is a display string built from the filter (`ville IN ('Lyon', 'Paris', 'Marseille')`, `montant > 100`, `siret IS NULL`), never sent to a server and never parsed back; a long `In` list is cut after 3 values with `+N`.
7. **Value list of the column menu**: the distinct values of the loaded rows with their counts (cap 500 distinct values, then a hint line `500 premières valeurs`), NULL as its own row, sorted by count descending then value; the list does not depend on the other filters (counts are over all loaded rows).
8. **Export stays the whole committed result** (unchanged behavior); the export menu title keeps its figure. Exporting the filtered view is a follow-up, not built.
9. The filter, the search text and the sort belong to one result tab and die with it; nothing is persisted.

**Palette (M13)**
10. **A window-level overlay**, opened by `Ctrl+K` and by a click on the title bar search box (which stops being a disabled placeholder), closed by `Échap`, by a click on the dimmed area and by running an item. One palette per window.
11. **Modes by prefix** typed as the first character: none = `Tout`; `>` actions, `#` objects, `:` go to line, `!` history. The mode pills do the same and rewrite the prefix. `@ Symboles` and the `FICHIERS` section have no feature behind them and are not drawn.
12. **Matching** is a case- and accent-insensitive subsequence match with a score (exact > prefix > word start > consecutive run > scattered; shorter names first on ties); the matched characters are returned so the head can color them. Empty query: `Tout` shows the actions and the 5 most recent history entries only; `>` all actions; `#` nothing (a hint line); `!` the 50 most recent entries.
13. **Sections in `Tout`** in the order Objets, Actions, Historique, max 5 / 5 / 3 rows each (the full lists are one prefix away). The footer shows `{n} résultats · {ms} ms` (time of the last search, measured with `Stopwatch`).
14. **Run rules.** Action: `Entrée` runs it if it can run (otherwise the row is shown disabled with no effect). Object: `Entrée` opens the table data tab or the definition (existing explorer behavior); `Ctrl+Entrée` opens a new query tab with `SELECT * FROM <quoted name>` for tables, views and materialized views and behaves like `Entrée` for the other kinds. History: `Entrée` appends the statement to the active query tab (after a blank line, caret on it; a new tab when there is none), `Ctrl+Entrée` opens it in a new tab; **a history entry is never executed by the palette**. Line (`:12`): moves the caret of the active editor to that line (clamped), `Entrée` only. The palette closes before the command runs, so a confirmation dialog of the command is not hidden behind it.
15. **Objects** come from every open session, tables, views, materialized views, functions, procedures, triggers; each row shows the kind and the schema, the connection name and its environment square; the active connection's objects rank first; the matcher runs off the UI thread with a cancellation on each keystroke (a stale result never replaces a newer one); a cap of 200 candidates per search is returned before the section limits apply.
16. **Action list** (final for this phase; an action is listed only if it exists and shows its shortcut only when both heads bind it): New query tab, Close tab, Run, Run all, Cancel, Format document, Explain, Analyze, Commit (valider la transaction), Rollback (annuler la transaction), Switch to auto-commit / manual transaction, New connection, Disconnect, New table, Open diagram, New terminal, Open settings, Check for updates, About, Clear grid filter (only with an active view). Their texts are `UiText` keys `palette.action.*`; the category column (`Requête`, `Édition`, `Outils`, ...) uses the menu names the heads already have. Actions that need an active query tab are disabled without one.
17. Everything is `UiText` (fr and en, parity tests green, scanner green); the `Échap`, `naviguer`, `ouvrir`, `nouvel onglet` footer texts reuse the keys that exist for the completion popup when they exist.

No new project, no new package, no UI framework type in Presentation.

## 5. Risks (the card that touches one handles it explicitly)

- **Row identity** (P17-03, P17-04): a view row is not a source row; selection, preview, copy and the edit controller all use `DisplayGrid` rows, so the view must reset the selection when it changes and must never be the target of an edit.
- **Large results** (P17-03): 100,000+ loaded rows; a rebuild must not freeze the UI thread and a stale rebuild must never replace a newer one (the pattern of P16-01).
- **Focus and keys** (P17-14, P17-15): `Entrée` in the palette must not reach the editor behind it, `Ctrl+K` must work from the editor, the grid and the explorer, and the overlay must sit above the Win2D / custom-drawn grid.
- **Heads drift**: both heads share every rule through the view-models; a head card never re-implements matching, ordering, operator availability or texts.
