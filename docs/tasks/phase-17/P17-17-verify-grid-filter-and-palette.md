## Goal

## Design decisions (final)
- Automated, `tests/Shared/GridFilterFlowScenario.cs` (pattern of `QueryFlowScenario` / `TransactionFlowScenario`), per engine, through `QueryTabViewModel`, `SessionManager` and the real provider: a query returning typed columns (integer, decimal, text with accents and a NULL, date-time, boolean where the engine has one, a guid where it has one) over a small seeded table; then (1) a typed filter per category (`>` on a number, `>=` on a date, `Contains` on accented text, `IsNull`, `Equals` on a boolean) gives the expected rows and `FooterText` counts; (2) the value list of a column has the right counts and the NULL row, applying two values produces an `In` view; (3) sort ascending and descending on each category (NULL placement, accented text order, number order not text order); (4) search over several columns; (5) while a filter is active a grid edit is refused (`ReadOnlyReason == filtered`) and after `ClearFilters` the same edit works and commits (single-table result on every engine); (6) pending edits block adding a filter; (7) export while filtered still writes every loaded row; (8) a 50,000 row result (generated by the engine, `generate_series` / recursive CTE / numbers table / `WITH RECURSIVE`, each dialect its own) is filtered and sorted without blocking the test's dispatcher thread for more than a generous bound. SQLite runs always, the others Docker-gated (`rtk pwsh eng/run-docker-tests.ps1 -Engine all`).
- Automated palette flow in `tests/Squill.Presentation.Tests/Palette/PaletteFlowTests.cs` through `WorkspaceViewModel` with two fake sessions (two connections, one Production, one Staging, same table name in both): `comm` in `All` returns objects of both connections, actions and history in the order of decision 13; `>` lists actions only and `Commit` is disabled without a transaction; `#` finds routines and triggers; `!` lists history newest first and `Enter` appends the statement to the active tab without sending anything to the fake connection; `:3` moves the caret; `Enter` on a table of the non-active connection activates that connection and opens the tab; `Ctrl+Entrée` opens a query tab with the quoted `SELECT *`; closing and re-opening resets the text; a language switch changes the titles and sections.
- Manual checklist `docs/verification/grid-filter-palette.md`, one section per head (WinUI first, Avalonia smoke), `SQUILL_LANGUAGE=fr` and once `en`, light and dark, boxes unchecked and a blank `Result` column: filter by a typed operator and by value list, funnel and sort arrow in the header, chip removal, search box and `Ctrl+F`, bar disabled with pending edits and the read-only marker while filtered, footer text, a filter on a result that is still streaming, a 100,000-row result stays responsive; palette `Ctrl+K` from editor / grid / explorer, title bar click, every mode pill and prefix, `Enter` / `Ctrl+Entrée` / `Esc` / click outside, focus return, no key reaching the editor, history insert, go to line, objects of two connections with environment squares, narrow window, screen reader. Compare with M05 and M13 and list every visible difference. It also lists the known limits of the ADR (client-side filter over loaded rows, read-only while filtered, export is unfiltered, no freeze / hide / fit width, no symbols or files section).
- Bugs found: fix in this commit when under ~30 lines with a regression test, else a new card `P17-19` onwards (added to the index); a known gap is listed in the report, not hidden.
