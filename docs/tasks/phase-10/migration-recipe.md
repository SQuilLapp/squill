# Phase 10 - Migration recipe (shared by P10-10 ... P10-16)

Each migration card moves the hard-coded user-visible strings of one area into the two catalogs, in BOTH heads and in the Presentation code of that area, in one commit. This file is the common procedure; the card only names the area and its files.

## Rules (final)
1. **Scope = inventory.** Open `docs/tasks/phase-10/inventory.md` (P10-03), find the sections of your area. Every line is either migrated or moved to `tests/Squill.Presentation.Tests/i18n/ignored-literals.txt` with a reason (only for text that is not UI: SQL, identifiers, file formats, developer-only exceptions, glyphs). Tick the line (`- [x]`) and append ` -> <key>` or ` -> ignored`. Never leave an unticked line of your area. A candidate that belongs to another area is ticked by that area's card, not yours.
2. **Keys.** English dotted identifiers `<area>.<thing>` (`connection.error.nameRequired`, `designer.title.new`), lower camel case after the first dot. Reuse an existing key when the text is the same (look first). Plurals: `<key>.one` and `<key>.other`, called through `UiText.FormatPlural`. Placeholders `{0}`, `{1}`; never concatenate translated fragments, one key per sentence.
3. **Both catalogs in the same commit.** `UiTextCatalogFr` keeps the French (reuse the French already shown by the app or the mockups, same spelling, straight apostrophe `'`, no non-breaking spaces); `UiTextCatalogEn` gets natural English (sentence case, same punctuation and placeholders). The parity test from P10-02 must pass.
4. **Presentation code.** Replace the literal by `UiText.Get`/`UiText.Format`/`UiText.FormatPlural` at the point of use (not cached in a static or a field of a long-lived object). Message codes from P10-09 are rendered with `UiText.Format("issue.<code>", args)`.
5. **Not translated** (final): the message text of a database engine or driver exception (`ex.Message` stays verbatim, shown after a translated heading such as `Connexion impossible` / `Connection failed`), SQL text, keywords, function and type names, identifiers and user data (names, cell values, file paths), the `NULL` marker, log text, developer-facing exception messages (`ArgumentException`, guards) which must never reach the user: if one currently does, the view-model checks the condition first and shows a catalog message instead.
6. **Avalonia markup:** `{loc:Text key}` for any string property (`Text`, `Content`, `Header`, `Watermark`, `ToolTip.Tip`, `AutomationProperties.Name`, ...). **WinUI markup:** `loc:Loc.Key` and the attached properties added by P10-08; code-behind uses `UiText.Get`. Tooltips and automation names count as user-visible text.
7. **Tests.** For each migrated area add tests in the matching test project: at least one Presentation test per migrated message that runs the code path under `UiText.Override(UiLanguage.French)` and `UiText.Override(UiLanguage.English)` and asserts the expected text in each language (no English word in the French run, no French in the English run). Head tests only for helpers and formatting that can run headless.
8. **Check in English.** After the build, launch each head with `SQUILL_LANGUAGE=en` and `SQUILL_DATA_DIR` pointing to a throwaway folder, open the screens of the area and capture them with the tools of P9-02 (`tools/visual/`, procedure in `docs/design/visual-spec.md` section 11); repeat once with `SQUILL_LANGUAGE=fr` to confirm nothing regressed. A screen that cannot be driven is listed in the report as "to check by hand". Stop every process you started.
9. **Layout.** English text must not clip or overlap: when a string is longer than the French one, fix the control (min width, wrapping, trimming with tooltip) instead of shortening the translation.

## Common acceptance criteria (each migration card repeats only what differs)
- `rtk bypass dotnet build Squill.Windows.slnx -c Release -warnaserror` exits 0 with 0 warnings.
- `rtk bypass dotnet test --solution Squill.Windows.slnx -c Release` is green (catalog parity and used-keys tests included).
- Every inventory line of the area is ticked; the card's `Status` and the index line are updated.
- No process left running (apps, `dotnet build-server`, AOT executables).
