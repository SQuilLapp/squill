# P21-05 - Sql: Oracle dialect (tokenizer, splitter, keywords, quoting, types, functions)

Status: done
Depends on: none

## Goal
The SQL layer knows Oracle instead of falling back to the generic ANSI behaviour: highlighting, statement splitting, completion keywords, quoting, the type catalogue and the function catalogue.

Exists today: `SqlTokenizers.For(dialect)` with PostgreSQL, SQLite, MySQL and T-SQL tokenizers (P3-02, P3-03); `SqlQuoting`, `DataTypeCatalog`, `FunctionCatalog`, keyword lists per dialect; Oracle uses the generic path.

## Design decisions (final)
- `OracleTokenizer`: `"quoted"` identifiers, `q'[...]'` alternative quoting, `N'...'`, `:name` bind parameters, `--` and `/* */` comments, no backticks.
- Statement splitter: a PL/SQL block (`BEGIN ... END;`, `DECLARE`, `CREATE [OR REPLACE] FUNCTION|PROCEDURE|PACKAGE|TRIGGER|TYPE`) ends at a line holding only `/`; other statements end at `;` (the trailing `;` is stripped before sending, as the bridge does today).
- Quoting: upper-case folding (an unquoted name is upper case), quote when not `[A-Z][A-Z0-9_$#]*` or reserved (P19-01 rule).
- Type catalogue: `NUMBER(p,s)`, `VARCHAR2`, `NVARCHAR2`, `CHAR`, `CLOB`, `BLOB`, `DATE`, `TIMESTAMP [WITH [LOCAL] TIME ZONE]`, `RAW`, `BINARY_FLOAT/DOUBLE`, `JSON` (23c).
- Function catalogue: the common scalar and aggregate functions (`NVL`, `NVL2`, `DECODE`, `TO_CHAR`, `TO_DATE`, `SYSDATE`, `SYSTIMESTAMP`, `LISTAGG`, ...), with signatures for signature help.
- TextMate grammar generated by `tools/Squill.GrammarGen` for Oracle.

## Done notes
- Added `OracleTokenizer` and `OracleKeywords`; the splitter treats a line holding only `/` as the end of a statement and keeps the inner `;` of `BEGIN`/`DECLARE` blocks and of `CREATE [OR REPLACE] [EDITIONABLE|NONEDITIONABLE] FUNCTION|PROCEDURE|PACKAGE|TRIGGER|TYPE`. Other dialects are untouched (their splitter tests ran unchanged).
- `IdentifierQuoting` (and `AliasGenerator` reserved words) know Oracle; `DataTypeCatalog`, `FunctionCatalog` and the keyword completion (`FETCH FIRST`, Oracle statement starters) have Oracle entries; `DUAL` is a known table for Oracle diagnostics (needed by the corpus).
- Grammar `assets/grammars/sql-oracle.tmLanguage.json` generated by `tools/Squill.GrammarGen`.
- Corpus `tests/Shared/SqlCorpus/oracle.{valid,invalid}.sql`: 22 valid entries accepted by the Oracle Free container (Podman, `eng/run-docker-tests.ps1 -Engine oracle`), one marked `-- unsupported: CONNECT BY` for the parser (parser coverage of Oracle syntax is not in this card). `SqlCorpusScenario` sends the pieces of a multi-statement Oracle entry one by one.
- Not changed: `SqlQuoting` (always quotes, DDL generator is P21-06).
