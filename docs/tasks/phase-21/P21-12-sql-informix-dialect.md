# P21-12 - Sql: Informix dialect (tokenizer, splitter, keywords, quoting, types, functions)

Status: done
Depends on: P21-106

## Goal
Highlighting, splitting, completion and hover for Informix instead of the generic fallback.

Exists today: per-dialect tokenizers and catalogues (see P21-05 for Oracle); since P21-106 an `InformixTokenizer` exists (`{ }` comments, `?` and `:name` parameters, ANSI keywords only): extend it instead of writing a new one. The editor still underlines `FIRST` in `select first 5 ...` and treats the statement as read-only (`EditableSourceAnalyzer`).

## Design decisions (final)
- Tokenizer: `{ ... }` comments in addition to `--` and `/* */`; `"..."` is a string unless `DELIMIDENT` is set (default: treat `"` as identifier quotes, the DRDA default; record the choice in the card); `?` parameters.
- Splitter: `CREATE PROCEDURE|FUNCTION ... END PROCEDURE|FUNCTION;` is one statement.
- Keywords and functions: `FIRST n`, `SKIP n`, `MATCHES`, `NVL`, `DECODE`, `TODAY`, `CURRENT YEAR TO SECOND`, `MDY`, `EXTEND`.
- Types: `SERIAL`, `SERIAL8`, `BIGSERIAL`, `INT8`, `DECIMAL(p,s)`, `MONEY`, `LVARCHAR`, `DATETIME <q> TO <q>`, `INTERVAL`, `BYTE`, `TEXT`, `BLOB`, `CLOB`, `BOOLEAN`.
- Quoting: lower-case folding.

## Out of scope
- DDL generator, formatter rules beyond keywords.

## Done notes
- Exists-today check: `InformixTokenizer` had `{ }` comments and `:name` parameters but not `?` (the P21-106 note said it did) and used the ANSI keywords; it now also reads `?` and uses `InformixKeywords` (ANSI plus `FIRST`, `SKIP`, `MATCHES`, `TODAY`, `EXTEND`, `MDY`, the Informix type names, `PROCEDURE`, `FUNCTION`...).
- Added: splitter rule (`CREATE [DBA|OR REPLACE] PROCEDURE|FUNCTION ... END PROCEDURE|FUNCTION;` is one statement, inner `;` kept); parser: `SELECT [SKIP n] [FIRST n] [DISTINCT|UNIQUE]` (`FIRST` is only a row count when a number or parameter follows, so a column named `first` still parses; `FIRST` fills `Top`, `SKIP` fills `Offset`), the `MATCHES` / `NOT MATCHES` operator, `CURRENT <q> TO <q>` and `EXTEND(x, <q> TO <q>)`; the system catalogue (`sys*` tables) is not reported as an unknown table; lower-case folding in `IdentifierQuoting` (a name with capitals or a keyword is quoted with `"`); function catalogue (NVL, DECODE, TODAY, MDY, EXTEND, DAY/MONTH/YEAR, ...), type suggestions, statement starters and `FIRST`/`SKIP` completion, alias reserved words; grammar `assets/grammars/sql-informix.tmLanguage.json` (generated by `tools/Squill.GrammarGen`, also run by `GrammarTests`).
- Decision recorded: `"..."` is an identifier quote (`DELIMIDENT` set, the DRDA default), as in the generic tokenizer; a server session without `DELIMIDENT` would read it as a string, which is not modelled.
- Corpus: `tests/Shared/SqlCorpus/informix.valid.sql` (19 entries) and `informix.invalid.sql` (5) run in `Squill.Sql.Tests`; the valid entries also ran against the Informix 15.0.1 container (`SqlCorpusTests` in `Squill.Data.Informix.Tests`, new `sqcorpus` logged database, sample schema created by the test). The server rejects `select distinct first 2 ...`: the order is `FIRST n DISTINCT`.
- Fixes the editor behaviour seen in P21-106: `select first 5 ...` no longer has a parse error, so `EditableSourceAnalyzer` treats it as a single SELECT (test `Analyze_SelectFirst_IsEditable`). The reason texts of that analyzer are English literals, not `UiText` keys: out of this card's area, carded as [P21-112](P21-112-editable-source-reasons-uitext.md).
- Not done (out of scope or not asked): formatter rules, DDL generator, `SET ... ` / `DBINFO` specifics, `FOREACH` / SPL statements inside procedure bodies are not parsed (only split correctly), `DELIMIDENT` off.
- Not driven in a published exe: the highlight of `FIRST` and the editable grid after `select first N` (the parser path is covered by unit tests only).
