# P21-06 - Sql: Oracle DDL generator (CREATE, ALTER, DROP) for the table designer

Status: todo
Depends on: P21-04, P21-05

## Goal
The table designer and the multi-table drop work on Oracle.

Exists today: `IDdlGenerator` with PostgreSQL, MySQL, SQL Server and SQLite generators (`DdlGenerators.For`), `DdlWriter`, `TableDropPlan`; Oracle has no generator.

## Design decisions (final)
- `OracleDdlGenerator`: `CREATE TABLE` with identity (`GENERATED BY DEFAULT AS IDENTITY`), inline PK/FK, `ON DELETE CASCADE|SET NULL` only (Oracle has no `ON UPDATE` and no `RESTRICT`: the validation of P7-08 reports them as errors for Oracle); `ALTER TABLE ... ADD`, `MODIFY`, `RENAME COLUMN`, `DROP COLUMN`; `CREATE INDEX`, `DROP INDEX`; `DROP TABLE` without `CASCADE CONSTRAINTS` (phase 20 rule).
- DDL is not transactional: the designer warns as for MySQL (`UsesTransactionalDdl` false since P21-03).

## Out of scope
- Partitioning, tablespaces, storage clauses.

## Tasks
- [ ] Golden-text tests per operation.
- [ ] Docker-gated create and alter matrix on Oracle (P11-30 pattern), multi-table drop proof (P20-09 pattern).

## Acceptance criteria
- Recipe 2 common acceptance; `-Engine oracle` green.

## Risks
- Changing a column type of a non-empty column is refused by Oracle in many cases: surface the engine error, do not emulate a rebuild.
