# P11-28 - Completion, hover, signature help and formatter per dialect

Status: todo
Depends on: P11-27, P11-17, P11-18, P11-19

## Goal
Editor intelligence is correct for each dialect on the shared sample schemas: right quoting, right keywords and functions, objects of the new schema kinds, a formatter that never changes meaning.

## Design decisions (final)
- Completion tests (`Squill.Sql.Tests`, data-driven by a table `dialect, text-with-caret, expected items, unexpected items`) on the sample schema snapshots (built from the readers' output stored as JSON test resources captured once from the containers, generated by a Docker-gated test that rewrites them only when `SQUILL_UPDATE_SNAPSHOTS=1`): identifiers needing quotes are quoted per dialect (`"`, backtick, `[ ]`), schema-qualified completion (`public.`, `dbo.`, `db.`), aliases and CTE columns, `INSERT INTO t (` columns, `JOIN ... ON` suggestions from foreign keys, functions and routines of the schema (from P11-15: user functions complete as functions with their `Signature`), `TOP`/`LIMIT`/`FETCH` only in their dialect, no `ILIKE` on MySQL/SQL Server, no `ISNULL` on PostgreSQL, 15 cases per dialect.
- Function catalog audit: for each dialect compare `FunctionCatalog.For(dialect)` with a list of the 40 most used built-in functions of that engine (written in the test as a literal list) and add the missing signatures with parameter docs; signature help tests for 5 functions per dialect.
- Hover: table, column (type, nullability, key, FK target), view (shows definition first line), function; per dialect 4 cases.
- Formatter: for every valid statement of the P11-27 corpus, `SqlFormatter.Format` output (a) tokenizes to the same non-whitespace token sequence as the input (comments and literals unchanged) and (b) is stable (`Format(Format(x)) == Format(x)`); fix formatter bugs, never skip corpus lines.

## Out of scope
- New completion features, fuzzy ranking changes.
